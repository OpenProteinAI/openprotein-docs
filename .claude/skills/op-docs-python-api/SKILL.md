# Python API reference pages

Twelve pages under `/python-api/api-reference/*`, replacing `sphinx.ext.autodoc` +
`sphinx.ext.viewcode` + `sphinx.ext.napoleon`. **61 documented classes, 439 members, 501
dotted anchors**, generated by static analysis of `openprotein-python` 0.16.1 — the SDK is
never imported. All 12 pages prerender.

The generator is scored against what the old Sphinx site actually published:

```
member sets: 61 exact / 61 classes   members 439 generated vs 439 rendered by Sphinx   kinds all match
member order: 60 match / 61   differs: openprotein.fold.FoldResultFuture
signatures & types: 484 exact / 501   3 overload-primary, 14 typed-beyond-sphinx   no unexpected drift
documented types: 657 exact / 679   7 docstring-stale, 15 griffe-tuple-normalised   no unexpected drift
all checks passed — 501 dotted anchors present and unique, 659 cross-references resolve
51/51 line-linked SDK files match sdk-pin.json at 85dc94bd15a3 — every [source] line number is anchored
```

## The invariants worth memorising

1. **Element ids are the dotted paths Sphinx used, verbatim and unslugified.**
   `…/fold.html#openprotein.fold.FoldAPI.get_results` still resolves. Never slugify them.
2. **`specs/` is generated and committed.** Never hand-edit; `pnpm check:pyapi` compares bytes.
   After `pnpm sync:pyapi`, **restart `pnpm dev`** — `readFile` is not watched.
3. **`pages.json` is the curation, and the only source of it.** `__old/` is deleted in Phase 10.
4. **`pythonApi` frontmatter is a boolean flag**, not a module name — a page draws on up to five
   modules, and the classes are declared inline with `<PyClass>`.
5. **A class body stays mounted when collapsed.** Every member id must be in the DOM because
   fumadocs' TOC registers anchors once via `getElementById`.
6. **The anchor lives on the card's heading row**, not the card — an expanded class is taller
   than the viewport and would never satisfy the TOC's IntersectionObserver.
7. **Only ever link what this site documents.** A dotted child is linked only if it is a
   *documented member*; `Type[NullMSA]` resolves to a nested class autodoc never emitted.
8. **`Parser.auto` is not enough**, and sections come from whichever object owns the docstring.
   Both are load-bearing; together they recovered 34 of the 495 docstrings in the corpus.
9. **Signatures carry no annotations, and that is correct.** `autodoc_typehints = "description"`
   moved them into the parameter table. But defaults *are* resolved (`interval=5`, not
   `config.POLLING_INTERVAL`) and the class signature comes from the **MRO** `__init__`, or 11
   classes render `()`. `pnpm diff:pyapi` scores all of this.
10. **`[source]` links resolve through the pinned commit, never the tag**, and
    `pnpm verify:pyapi:pin` re-proves the wheel is that tree. A moved tag would silently
    re-point every one of the ~500 line ranges.

## Recipes

**Regenerate the specs** — `pnpm sync:pyapi`, restart `pnpm dev`, then
`pnpm check:pyapi && pnpm diff:pyapi && pnpm build && pnpm check:pyapi:render`.
Needs the venv: `python3.13 -m venv .venv-pyapi && .venv-pyapi/bin/pip install -r scripts/pyapi/requirements.txt`.
→ `references/verifying.md`

**Add or remove a documented class** — edit `scripts/pyapi/pages.json` (the section's `entries`),
then `sync:pyapi`, then add or remove the `<PyClass path="…" />` line and the path in its
`<PyGroup anchors={[…]}>`. `diff:pyapi` will say **nothing** about a class `golden/` lacks — it
`continue`s past it and the `61 exact / 61` line does not move — so verify a new class by hand.
→ `references/generator.md`

**Change which members appear** — `select()` in `members.py`. Every clause was forced by a
specific failure against the oracle; read the table before touching it.
→ `references/generator.md`

**A signature looks wrong** — run `pnpm diff:pyapi` and read the `signatures & types` line. It
compares against the signature the live Sphinx page rendered, which `golden/` captured verbatim.
→ `references/oracle.md`

**A type is not linked** — either it is not documented here (correct — `str`, `Sequence`), or
the resolver could not map its canonical path. → `references/docstrings.md`

**RST leaking into prose** — `lib/python-doc.ts` handles roles, `` ``literals`` ``,
`.. code-block::`, `>>>` doctests and `.. note::`. Anything else arrives verbatim.
→ `references/docstrings.md`

**A docstring section renders as a paragraph** — `parsed_sections()` picked no structure. Run
`pnpm sync:pyapi` and read the WARN. → `references/docstrings.md`

**A member has prose but no parameter table** — it is inherited, and the sections must be
parsed from the ancestor that owns the docstring. → `references/generator.md`

## Known gaps, carried deliberately

- **One class's member order differs.** Sphinx's `bysource` keys on
  `tagorder.get(name, len(tagorder))` — the dict's *size*, not max+1 — so inherited members tie
  with whichever own member sits at that index and the groups interleave. We emit own-by-source,
  then inherited, then docstring-only, which matches Sphinx for **60 of 61** classes;
  `openprotein.fold.FoldResultFuture` is the exception. `diff:pyapi` reports it by name.
- **Two signature classes deliberately differ from the live page**, both asserted as expected by
  `diff:pyapi`: 14 attributes where we print a type Sphinx left blank (napoleon `.. attribute::`
  entries and pydantic fields), and 3 members where Sphinx printed the first `@overload` and we
  print the implementation signature plus every overload.
- **Two anchors change**, both off Sphinx's numeric fallback: `models#id1` → `#results-1` and
  `index#id1` → `#models-1`, each the second heading of a duplicated title. Also unpublished:
  the 11 `openprotein-<page>` h1 slugs, which pointed at the top of their own page anyway.
- **Three `autosummary` targets are documented by no `autoclass`** (`svd.SVDAPI`,
  `umap.UMAPAPI`, `predictor.PredictionResultFuture`). Sphinx silently dropped those rows;
  we render all 47 and leave those three unlinked.
- **`openprotein.Protein` and `openprotein.Model`** are cross-referenced by the old prose but
  documented nowhere. Plain code spans here is **parity, not a gap** — Sphinx dropped the
  reference and printed bare `<code>` too.
- **One walkthrough link is plain text** — `PoET-2_inverse_folding.ipynb` has no wrapper page
  yet. `extract_manifest.py` warns about it on every run.
- **Eight upstream SDK docstring defects** surface as ten griffe warnings on every `sync:pyapi`:
  a parameter documented that does not exist in the signature, and at two of those sites the
  parameter is also untyped, so they warn twice. Report upstream rather than reproducing them.
- **`.venv-pyapi` is currently built from `__old/.pixi`'s Python 3.13**, which disappears with
  `__old/` in Phase 10. The repo will need its own interpreter pin by then.

Every one of these is written up with its mechanism in the reference file for its area. Most of
this subsystem's rules exist because something failed silently once — read the file before
changing the behaviour it describes.
