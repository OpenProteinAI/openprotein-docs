# The renderer — `lib/python-api.ts` and `components/python-api/`

## Server → client boundary

| file | runs | notes |
|---|---|---|
| `lib/python-api.ts` | server | `import 'server-only'`, `node:fs`, `react.cache` |
| `lib/python-doc.ts` | server | `server-only`; pulls shiki through `lib/markdown.ts` |
| `components/python-api/py-class.tsx` · `py-function` · `py-summary` · `sections` | server (async) | read specs, render markdown |
| `components/python-api/collapsible.tsx` | **client** (`'use client'`) | `PyGroup`, `PyCard` — the only stateful pieces |
| `components/python-api/signature` · `source-link` · `type-ref` | no directive | plain leaves, used from server components |
| `components/copy-button.tsx` · `components/use-hash-target.ts` | client | **shared with the REST reference** |

The split matters: everything that reads a spec or renders markdown is a server component, so no
spec JSON and no shiki reaches the browser. Only the collapse state is client-side.

## The reader

```ts
readPyEntry(dotted) -> { entry, document }   // cache()d; throws loudly on an unknown path
readPySummary(paths) -> PySummaryRow[]       // autosummary rows
pySourceUrl(document, source) -> string | null
pyAnchor(dotted) -> string                   // identity — see below
pyToc(pagePath, toc) -> TOCItemType[]
```

`cache()` rather than a module-level `Map`: a module-level cache goes stale the moment
`pnpm sync:pyapi` rewrites the file, because `specs/` is read with `readFile` and never imported,
so nothing invalidates it. Per-request is the right lifetime — and **`pnpm dev` still needs a
restart** after a sync, because nothing watches `specs/`.

`readPyEntry` **throws** on a path that does not resolve, naming the known paths. Rendering
nothing would hide a typo in a page for as long as nobody compared it to the old site.

## Anchors

`pyAnchor` is the identity function, deliberately. Element ids are the dotted paths Sphinx used,
**verbatim and unslugified** — `openprotein.fold.FoldAPI`, `openprotein.fold.FoldAPI.get_results` —
so the *fragment* of every inbound deep link still names a live element. Members are
`` `${owner}.${member.name}` ``.

The **path** half is not handled here and does not work yet: nothing in the repo maps
`…/api-reference/fold.html` to the extensionless route, so that URL 404s today. The blanket
`.html` → extensionless 301 is Phase 9's `proxy.ts`. Keeping the fragments verbatim is what makes
that redirect sufficient when it lands.

Group ids are the rehype-slug of the heading text, generated by `seed_pages.py` so `#models`
still resolves after the heading moved out of MDX into `<PyGroup>`. Duplicates get a `-1`
suffix: `models#results-1` and `index#models-1`, the only two anchors this migration changes —
Sphinx numbered both `#id1`. `slugify()` shares its `seen` counter across the whole page, so any
future duplicate heading text behaves the same way.

## The TOC

`pyToc(page.path, toc)` builds the page TOC by scanning the **raw MDX**, because everything on a
reference page renders at request time — the `<PyGroup>` headings as much as the classes inside
them — so fumadocs' compile-time TOC sees almost nothing.

- `<PyGroup id title>` → depth 2, using the id and title from the source.
- `<PyClass path>` / `<PyFunction path>` → depth 3 (clamped at 4), titled with the last dotted
  component.
- Ordinary markdown headings (the index page's `##`s) are taken from `toc` **in order**, so their
  compile-time slugs are used verbatim rather than re-slugified — re-slugging is how anchors
  drift. A trailing heading after the last component is appended.
- Fenced regions are skipped.

The route calls it only when `page.data.pythonApi` is true.

## Collapse — `collapsible.tsx`

| | default | when hidden |
|---|---|---|
| `PyGroup` (a section) | **open** | children stay **mounted**, hidden with `hidden` |
| `PyCard` (a class or function) | **closed** | body stays **mounted**, hidden with `hidden` |

Both stay mounted, and that is the important difference from the REST reference. There the
endpoint bodies are lazy because each mounts a playground and an interactive schema tree. Here
there is nothing expensive inside — static server-rendered HTML — and **every member id has to
remain in the DOM** because fumadocs' TOC registers its anchors once via `getElementById` and
never re-registers.

Classes are collapsed because a reference page is a lookup surface: `openprotein.embeddings` is
179 members if everything is open at once.

`PyGroup` calls `useHashTarget([id, ...anchors], …, { descendants: true })` so it opens for any
hash that is a dotted descendant of a class inside it — the embeddings page would otherwise need
179 anchors listed in its MDX. `PyCard` targets its own id plus its members' and, on a hit,
re-runs the scroll inside `requestAnimationFrame`: the browser's own fragment scroll ran while
the card was still collapsed and the target had no box.

`use-hash-target` also listens for **`popstate` as well as `hashchange`** (no browser fires
`hashchange` when the clicked fragment already equals `location.hash`, so clicking the same TOC
entry twice would be dead), and catches the `URIError` a malformed fragment like `#%` throws out
of `decodeURIComponent`.

## The card header

The anchor and the flex layout are the `<h3>` itself. Contents, in order: chevron · kind badge ·
dotted name · signature · return type — then, as **siblings of the toggle**: member count ·
Copy code · Copy link · source.

- Siblings, not children: a `<button>` inside a `<button>` is invalid HTML and browsers recover
  by dropping the inner one.
- The count lives in that trailing group rather than inside the toggle so all four controls share
  one `items-center` context and align by construction. Inside the toggle it sat 3px off the
  icons — 408/405/405/405. Verify by *spread*, not by an absolute figure: the centre depends on
  what precedes the card (340 on `predictor`, 373 on five pages, 401 on `fold`/`embedding`, 429
  on `models`, 469 on `openprotein`, 497 on `molecules`). Measured across all 12 pages: **62
  cards, 0 with a spread above 1px**.
- `pt-3` puts that row on the header's first line.
- Copy code yields the header as plain text (`openprotein.fold.FoldAPI(session)`); Copy link
  yields `origin + pathname + '#' + id` via `anchorUrl()`, not `location.href` with the hash
  swapped — the reader may have arrived on a URL carrying a query string.
- `CopyButton` is shared with the REST reference, same `Copy` / `Link2` icons. It avoids
  fumadocs' `useCopyButton`, which ticks on `Promise.resolve(onCopy()).then()` with no rejection
  branch, and whose synchronous throw escapes when `navigator.clipboard` is undefined on the
  plain-http LAN URL `next dev` prints.

## Members

`py-class.tsx`'s `Member` renders `<h4 id={owner.name}>` with the kind badge, the name, then
either a signature and `→ returns` (methods) or `: annotation` (attributes and properties) — all
types through `<TypeRef>`. Below: `inherited from <linked documented path>`, a note for the
synthetic `model_config`, any overload signatures, then prose and sections.

Prose is skipped when a parsed `text` section exists, otherwise the raw `doc` is rendered —
without that guard the summary printed twice. The same guard is on the class and function bodies,
where the raw docstring additionally still carries its NumPy `Attributes` block as plain text,
which is already rendered as members.

`<Sections>` resolves all prose to HTML **before** rendering rather than returning an array of
promises from `.map()`, and skips `attributes` on a class for the reason above.

## Styling

`--py-class` / `--py-function` / `--py-method` / `--py-property` / `--py-attribute` / `--py-type`
in `app/global.css`, defined on `:root` and redefined under `.dark`. Declared as tokens rather
than Tailwind utilities so the badge, its 12% background tint and the type colour all come from
one place. (`dark:` utilities would work too — `fumadocs-ui/css/lib/base.css` declares
`@variant dark (&:where(.dark, .dark *))`, so the variant is class-based here — but a token keeps
the three uses in step.)

Class bodies render **inside** the `DocsBody` prose context, and `not-prose` is applied per
element — 16 sites across 6 files: the group and card heading rows, the kind badge, the "Bases:"
line, the `inherited from` note, the pydantic note, the overload list, every section title, every
parameter row's name / type / default, the admonition wrapper, the source link and the
`<PySummary>` table. Never wrap the tree in one `not-prose` — it exempts the element it is on,
not just its descendants, so the docstring prose inside would lose its typography.
