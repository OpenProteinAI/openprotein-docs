This compatibility interface is deprecated. Use [`session.models`](/references/python-api/models) for model access.

Create embeddings for your protein sequences using open-source and proprietary models! Note that for PoET Models, you will also need to supply a [`Prompt`](/references/python-api/prompt#openprotein.prompt.Prompt).

<PyGroup id="transform-models" title="Transform Models"
  anchors={[
    "openprotein.svd.SVDModel",
    "openprotein.umap.UMAPModel",
    "openprotein.svd.SVDAPI",
    "openprotein.umap.UMAPAPI",

>

These models are overlaid on top of the base embeddings models to produce reduced/transformed embeddings. [`SVDModel`](#openprotein.svd.SVDModel) represents an SVD model which is suitable to reduce the high-dimensional embeddings returned by base embedding models, whilst maintaining semantic information, fitted on your [`AssayDataset`](/references/python-api/data#openprotein.data.AssayDataset). You can fit your own SVD from any model's [`fit_svd`](#openprotein.embeddings.EmbeddingModel.fit_svd). [`UMAPModel`](#openprotein.umap.UMAPModel) represents a UMAP model which is suitable to project the high-dimensional embeddings into a lower dimension (usually 2) for visualization, to understand the semantic grouping within your [`AssayDataset`](/references/python-api/data#openprotein.data.AssayDataset). You can fit your own UMAP from any model's [`fit_umap`](#openprotein.embeddings.EmbeddingModel.fit_umap).

The legacy [`session.svd`](#openprotein.svd.SVDAPI) and [`session.umap`](#openprotein.umap.UMAPAPI) interfaces are deprecated compatibility APIs. For new code, create and manage these estimators through [`session.models.SVD`](/references/python-api/models#openprotein.models.ModelsAPI.SVD) and [`session.models.UMAP`](/references/python-api/models#openprotein.models.ModelsAPI.UMAP).
