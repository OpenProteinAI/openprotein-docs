Use `session.jobs.list(...)` and `session.jobs.get_job(...)` to inspect job records. Use `session.jobs.get(...)` to load the result reader. A job record describes the submission and its status; the reader provides methods to wait for and read results.

`wait_until_done()` waits for a terminal status and does not establish success: a failed or canceled job is also done. It does not fetch results. Check the job status before interpreting completion; result readers have their own failure and timeout behavior.

Given a stored job ID, refresh and check the status before reading results:

```python
from openprotein.errors import AuthError, JobFailedException, TimeoutException
from openprotein.jobs import JobStatus

try:
    future = session.jobs.get(job_id)
    future.wait_until_done(timeout=600)
    if future.status == JobStatus.SUCCESS:
        results = future.get()
    else:
        print("Job ended:", future.status, future.job.failure_message)
except TimeoutException as error:
    print("Polling timed out:", error)
except JobFailedException as error:
    print("Job failed:", error)
except AuthError as error:
    print("Authentication failed:", error)
```

`refresh()` updates the stored job record; `wait_until_done()` polls and updates it without reading results. The base `Future.get()` raises `JobFailedException` for `FAILURE`; some specialized readers have their own checks. `TimeoutException` covers polling timeouts. Network requests can also raise `requests.exceptions.Timeout`, an API `HTTPError`, or `openprotein.base.TimeoutError` for a gateway timeout. A timeout does not imply that the job was canceled.

`FutureUnit.get()` and `FutureUnit.wait()` raise `JobFailedException` when the unit is known to have failed or been canceled. A collection read can raise `JobOutputsNotReady` if the results are not ready; a direct position read can instead raise `HTTPError`. `InvalidJob` indicates a missing or invalid job.

Use `job` from the [ESM2 embedding example](/references/python-api/models#interface) and choose a read based on what you need:

**Every position.** `wait()` waits for the job and reads its primary output, with one value per submitted position. Use `get()` if the job has already succeeded.

```python
embeddings = job.wait(timeout=600)
print(embeddings[0].shape)
```

**One position.** Use a zero-based position. `unit(0).wait()` waits for and reads just the first result. If that result is already available, use `get_item(0)`.

```python
embedding = job.unit(0).wait(timeout=600)
print(embedding.shape)
```

**One named output.** Check `job.outputs` for the names this job provides. Pass `output=` to select one by name. Different outputs can have different types. For this ESM2 job, `embeddings` is the primary output.

```python
print(job.outputs)
embeddings = job.wait(output="embeddings", timeout=600)
print(embeddings[0].shape)
```

See the [primary outputs and result types](/references/python-api/models#task-results) for other model tasks.

## Job records and reloading

Model-task records use [Job](#openprotein.jobs.Job). Supported task records reload through `session.jobs.get(...)` as the corresponding task future. A reloaded job does not always retain the exact future class returned at submission: GP training uses [PredictorModel](/references/python-api/predictor#openprotein.predictor.PredictorModel), GP cross-validation uses [CVResultFuture](/references/python-api/predictor#openprotein.predictor.validate.CVResultFuture), and prompt sampling loads a stored [Prompt](/references/python-api/data#openprotein.data.Prompt). Refer to each reader's result contract.
